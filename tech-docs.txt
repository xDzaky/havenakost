
Penerapan:

Geolocation memerlukan HTTPS dan izin pengguna. Jika pengguna menolak izin, pencarian berdasarkan lokasi/kecamatan tetap harus bisa digunakan.&#x20;

## **4. Neon + PostGIS — pencarian kost terdekat**

Dokumentasi:

* [PostGIS Documentation](https://postgis.net/documentation/?utm_source=chatgpt.com)
* [ST_DWithin](https://postgis.net/docs/ST_DWithin.html?utm_source=chatgpt.com)
* [ST_Distance](https://postgis.net/docs/ST_Distance.html?utm_source=chatgpt.com)
* [PostGIS Database Management](https://postgis.net/docs/using_postgis_dbmanagement.html?utm_source=chatgpt.com)

Ini penting karena Havena Kost memiliki fitur pencarian berdasarkan jarak.

Contoh kebutuhan:

* Mencari kost dalam radius 3 km.
* Mengurutkan kost berdasarkan jarak terdekat.
* Memfilter kost berdasarkan kecamatan.
* Menampilkan lokasi kost pada peta.

Contoh SQL untuk menghitung jarak:

```
SELECT
  id,
  name,
  ST_Distance(
    location,
    ST_SetSRID(
      ST_MakePoint(:longitude, :latitude),
      4326
    )::geography
  ) AS distance_meters
FROM kost_listings
WHERE ST_DWithin(
  location,
  ST_SetSRID(
    ST_MakePoint(:longitude, :latitude),
    4326
  )::geography,
  3000
)
ORDER BY distance_meters ASC;
```

Ini mengasumsikan kolom `location` menggunakan tipe `geography(Point, 4326)`.

Jangan lupa:

* Aktifkan extension PostGIS di Neon.
* Gunakan spatial index GiST pada kolom lokasi.
* Simpan longitude dan latitude secara konsisten.
* Jangan menghitung jarak menggunakan perkiraan frontend jika database sudah bisa mengerjakannya.

PostGIS menyediakan fungsi jarak dalam meter dan mendukung penggunaan index untuk pencarian spasial.&#x20;

## Implementation Rules

### Maps

* Gunakan Leaflet + React Leaflet.
* Jangan menggunakan Google Maps API atau Mapbox.
* Pemilik menentukan koordinat kost dengan marker yang bisa digeser.
* Gunakan browser Geolocation API untuk fitur lokasi pengguna.
* Peta Next.js harus di-render sebagai client component.
* Jangan lupa import Leaflet CSS dan menentukan tinggi container peta.
* Tampilkan atribusi OpenStreetMap.
* Patuhi kebijakan penggunaan tile OpenStreetMap.

### Database & Location

* Gunakan PostgreSQL dan PostGIS.
* Aktifkan extension PostGIS.
* Gunakan tipe geography(Point, 4326) untuk lokasi kost.
* Tambahkan GiST spatial index.
* Gunakan ST_DWithin untuk pencarian radius.
* Gunakan ST_Distance untuk pengurutan berdasarkan jarak.
* Jangan menghitung jarak hanya berdasarkan perkiraan frontend.

### QR Code & Reviews

* Generate QR Code menggunakan package qrcode.
* QR Code harus mengarah ke URL review kost/kamar.
* Pengunjung tidak wajib login.
* Form review memuat nama, kamar, periode tinggal, rating, dan komentar.
* Review masuk ke status pending.
* Pemilik memverifikasi status penghuni.
* Pemilik tidak boleh mengedit rating atau komentar.
* Sediakan alasan ketika review ditolak.
* Admin memiliki kewenangan moderasi.
* QR Code bukan bukti identitas atau bukti penghuni.

### PDF

* Gunakan @react-pdf/renderer.
* Buat template laporan keuangan yang konsisten.
* Sediakan tombol download PDF.
* Ambil data laporan dari database, bukan data dummy.

### WhatsApp

* Gunakan Click to Chat melalui [https://wa.me/](https://wa.me/).
* Nomor disimpan dalam format internasional.
* Gunakan encodeURIComponent untuk pesan otomatis.

### Security

* Jangan pernah menaruh secret key pada frontend.
* Jangan mengekspos DATABASE_URL, R2_SECRET_ACCESS_KEY, TURNSTILE_SECRET_KEY, atau BETTER_AUTH_SECRET.
* Validasi input pada server.
* Verifikasi Turnstile di backend.
* Terapkan authorization berdasarkan role.
* Pemilik hanya boleh mengakses data kost miliknya sendiri.

### Development

* Baca dokumentasi resmi sebelum implementasi.
* Gunakan versi package yang kompatibel dengan versi React dan Next.js project.
* Jangan menggunakan package versi beta/next tanpa alasan yang jelas.
* Jangan membuat integrasi API eksternal yang tidak dibutuhkan.
* Jangan mengarang endpoint, method, atau konfigurasi.
* Pastikan setiap fitur bisa diuji sebelum melanjutkan ke fitur berikutnya.
* Jangan mengisi database produksi dengan data dummy.
* Gunakan environment variables untuk semua credential.

Jika dokumentasi atau kompatibilitas package berubah, prioritaskan dokumentasi resmi terbaru dan jelaskan perubahan sebelum menerapkan pendekatan berbeda.
